# Orme — 프로젝트 기능 확장 아이디어

> 3학년 2학기 수업 프로젝트용. 현재 앱을 "완결된 여행기록 서비스"로 끌어올리기 위한 기능 아이디어 모음.
> 각 기능에 **난이도(하/중/상)**, **평가 어필 포인트**, **필요 기술**을 표기.

---

## 현재 상태 진단

**지금 있는 것**
- Jetpack Compose 기반 UI (스플래시 / 로그인·회원가입 / 지도)
- 한국 지도(줌아웃 전국 ↔ 줌인 시군), 지역 탭 → 갤러리 사진을 지역 모양대로 크롭해 채우기
- 사진 수동 위치 조정 편집기, 교체/삭제
- 전국 모자이크 + 도별 완성도 색농도(뿌듯함), 광역시 통짜 단위

**부족한 것 (프로젝트로 얇아 보이는 이유)**
1. **서버/DB가 없음** — 전부 기기 로컬(`filesDir`) 저장. 기기 바뀌면 소멸.
2. **로그인이 껍데기** — 인증 로직 없음, 아무 화면이나 진입 가능.
3. **화면 흐름이 지도 하나뿐** — 여행"기록"의 깊이가 없음(지역=사진 1장).
4. **아키텍처/테스트 미비** — ViewModel/Repository 분리, DI, 테스트 없음.

## 우선순위별 추천

### 티어 A — 핵심 (이것만 해도 프로젝트 격이 확 오름)

#### A1. 백엔드 · 실제 인증 · 클라우드 동기화 ⭐가장 큰 임팩트
- **내용**: Firebase Auth(이메일/구글/카카오) + Firestore(여행 기록 DB) + Storage(사진). 로그인/회원가입 화면을 실제로 동작시키고, 내 지도를 클라우드에 저장 → 기기 바뀌어도 복원.
- **평가 어필**: 클라이언트–서버 구조, DB 스키마 설계, 클라우드 스토리지, 인증/세션 관리. 발표에서 "실제 서비스" 인상.
- **필요 기술**: Firebase(BaaS) 또는 직접 서버(Spring Boot / Node + PostgreSQL). Retrofit(직접 서버 시).
- **난이도**: 중~상

#### A2. 여행 기록 "일지"로 심화
- **내용**: 지역 탭 → 사진 1장이 아니라 **여행 일지 상세 화면**. 날짜, 제목, 메모, 사진 여러 장, 별점, 동행자, 경비, 태그. 한 지역에 여러 번 방문 기록.
- **평가 어필**: 실제 CRUD, 데이터 모델링, 리스트/상세 네비게이션. "지도 앱"→"여행기록 앱"으로 정체성 완성.
- **필요 기술**: Room(로컬 DB) 또는 Firestore, 상세 화면 Compose.
- **난이도**: 중

#### A3. 아키텍처 정비 (MVVM + Repository)
- **내용**: 화면 로직을 ViewModel로, 데이터 접근을 Repository로 분리. Hilt(DI), Room/Retrofit.
- **평가 어필**: 소프트웨어 공학 관점(관심사 분리, 테스트 가능성). 코드 리뷰/설계 점수.
- **난이도**: 중

---

### 티어 B — 권장 (완성도·차별화)

#### B1. 통계 · 업적 · 게이미피케이션 (이 앱의 '뿌듯함' 강화)
- 전국 정복률("34% 정복"), 도별 완성도 랭킹, 최다 방문 지역, 총 여행 수
- 배지/업적("첫 제주", "5개 도 완성", "10개 시군 달성")
- 연간 결산(스포티파이 Wrapped 느낌), 여행 캘린더/타임라인
- **평가 어필**: 데이터 집계·시각화(차트), UX 몰입도. **난이도**: 중

#### B2. 관광지 추천 (공공데이터 TourAPI) ⭐한국 프로젝트에 강추
- **한국관광공사 TourAPI**(공공데이터포털, 무료)로 지역별 "가볼만한 곳/맛집" 추천. 지역 누르면 그 지역 관광지 리스트 → 사진 찍으러 갈 곳 제안.
- **평가 어필**: 오픈 API 연동, JSON 파싱, 실용성. **난이도**: 중

#### B3. 위치/센서 활용
- GPS로 현재 위치 지역 자동 감지, 사진 EXIF에서 촬영 위치 자동 태깅·자동 지역 매칭
- **평가 어필**: 모바일 기기 기능(위치 권한, 센서) 활용. **난이도**: 중

#### B4. 지도 상호작용 고도화
- 전국 지도 핀치 줌/팬, 줌인↔줌아웃 전환 애니메이션, 지역 이름 라벨, 미방문/방문 지역 시각 구분 강화
- **평가 어필**: Canvas/제스처 심화, UX 디테일. **난이도**: 중

---

### 티어 C — 선택 (여유 있으면 / 차별화 한 방)

#### C1. AI 기능 (트렌디, 발표 임팩트 큼)
- 사진 자동 캡션/장면 분류(ML Kit, 온디바이스) 또는 LLM으로 사진·메모 기반 **여행 일기 자동 생성**
- 사진만 넣으면 어느 지역인지 추천
- **평가 어필**: ML/AI 접목. **난이도**: 중~상

#### C2. 공유 · 소셜
- 내 지도를 이미지로 내보내 SNS 공유(Share Intent), 친구 팔로우, 지도 비교, 랭킹 리더보드, 여행 기록에 댓글
- **평가 어필**: 소셜 그래프, 공유 플로우. **난이도**: 상

#### C3. 가고 싶은 곳(위시리스트/버킷리스트)
- 방문 기록과 별개로 "가고 싶은 지역/장소" 저장, 지도에 다른 색으로 표시
- **평가 어필**: 상태 구분 모델링, UX. **난이도**: 하

#### C4. 홈 화면 위젯 / 알림
- 홈 위젯에 정복률 % 표시, 여행 후 "기록 남기기" 리마인더 푸시, "이번 주말 근처 미방문 지역" 추천 알림
- **평가 어필**: 안드로이드 시스템 연동(Widget, WorkManager, FCM). **난이도**: 중

#### C5. 다크모드 · 다국어(i18n) · 접근성
- 라이트/다크 테마, 한/영 전환, TalkBack 대응
- **평가 어필**: 완성도·접근성 배려. **난이도**: 하

#### C6. 테스트 · CI
- 단위 테스트(ViewModel/Repository), UI 테스트(Compose), GitHub Actions CI
- **평가 어필**: 소프트웨어 품질/자동화. **난이도**: 중

#### C7. 여행 통계 대시보드 / 지출 관리
- 월별·지역별 지출, 이동 거리, 방문 빈도 차트 대시보드
- **평가 어필**: 데이터 시각화. **난이도**: 중

## 추천 조합 (로드맵 3안)

### 최소안 (안전하게 완성)
`A1 백엔드+인증` + `A2 여행일지` + `B1 통계/업적`
→ "로그인해서, 여행을 기록하고, 전국을 채워가며 성취를 보는" 완결된 서비스.

### 권장안 (밸런스 좋음) ⭐추천
`A1` + `A2` + `A3 아키텍처` + `B1 통계` + `B2 TourAPI 추천`
→ 서버·DB·오픈API·게이미피케이션까지. 기술 폭과 실용성 모두 잡음.

### 야심안 (차별화 한 방)
권장안 + `C1 AI(사진 기반 일기/지역 추천)` 또는 `C2 소셜(지도 공유·비교)`
→ 발표에서 "와" 포인트. 단, 시간 배분 주의.

## 제안 기술 스택 (권장안 기준)

| 영역 | 기술 |
|---|---|
| UI | Jetpack Compose (현재) |
| 아키텍처 | MVVM + Repository, Hilt(DI) |
| 로컬 DB/캐시 | Room |
| 백엔드 | Firebase (Auth / Firestore / Storage) *가장 빠름* |
| 네트워크 | Retrofit + OkHttp (TourAPI 등 REST) |
| 이미지 | Coil |
| 차트 | Vico / MPAndroidChart |
| 위치 | FusedLocationProvider |
| 비동기 | Coroutine + Flow |
| CI | GitHub Actions |

> 서버를 직접 만들어 보고 싶으면 Firebase 대신 **Spring Boot + PostgreSQL + JWT 인증**으로 대체 가능(백엔드 역량 어필엔 이쪽이 더 큼, 대신 공수 큼).

## 발표/평가에서 강조하면 좋은 포인트
- **문제의식**: "여행을 다녀도 기억이 흩어진다 → 지도를 채우며 모으는 재미(뿌듯함)"라는 명확한 컨셉.
- **차별점**: 단순 일지 앱이 아니라 **지도를 사진으로 정복**하는 시각적 성취.
- **기술 폭**: 클라이언트–서버, DB 설계, 오픈API, (있다면) AI/센서.
- **완성도**: 실제 인증·동기화가 되는 "돌아가는 서비스".

## 활용 가능한 공공데이터 / 오픈 API (실존)

> 대부분 **공공데이터포털([data.go.kr](https://www.data.go.kr))** 에서 회원가입 → 활용신청 → **서비스키(인증키)** 발급받아 무료로 사용.
> REST(JSON/XML) 형태라 Retrofit + OkHttp 로 연동. 하루 트래픽/호출 제한 있음(개발용은 충분).

### ⭐ 1순위 — 이 앱에 바로 맞음

| API | 제공기관 | 제공 데이터 | Orme에서 쓸 곳 |
|---|---|---|---|
| **TourAPI (국문 관광정보, KorService)** | 한국관광공사 | 관광지·맛집·숙박·축제·문화시설·레포츠·쇼핑, 대표이미지, 지역코드(areaCode/sigunguCode) 및 **GPS 기반 조회**, 키워드 검색, 상세정보 | 지역 누르면 "가볼만한 곳/맛집" 추천, 사진 찍으러 갈 곳 제안 (핵심) |
| **TourAPI 사진갤러리** | 한국관광공사 | 지역·키워드별 고품질 관광 사진 | 지역 소개 이미지, 빈 지역 미리보기 |
| **두루누비 정보서비스** | 한국관광공사 | 전국 걷기여행길·자전거길 코스 | "이 지역 걷기 코스" 추천 |

> **TourAPI 하나로 관광지·음식점·축제·사진·GPS조회·키워드검색이 다 되므로, 추천 기능은 이거 하나로 충분합니다.** (현재 버전 TourAPI 4.0, 호스트: `apis.data.go.kr/B551011/...`, `api.visitkorea.or.kr`)

### 2순위 — 지역/지도/코드 기반

| API | 제공기관 | 제공 데이터 | 쓸 곳 |
|---|---|---|---|
| **VWorld 오픈API** (`apis.vworld.kr`) | 국토교통부(공간정보 오픈플랫폼) | 배경지도, 행정구역 경계, **지오코딩(주소↔좌표)**, 좌표→행정구역 | GPS 좌표 → 시군구 자동 매칭, 사진 촬영지 지역 판별 |
| **SGIS 통계지리정보 오픈API** (`sgis.kostat.go.kr`) | 통계청 | 행정구역 경계, 인구·통계 지도 | 지역 경계 데이터 대안, 지역 통계 표시 |
| **행정표준코드관리시스템** (`code.go.kr`) | 행정안전부 | 법정동/행정동 코드 | 지역 코드 표준화(현재 kostat 코드와 매칭) |

### 3순위 — 정보 보강(있으면 풍부해짐)

| API | 제공기관 | 제공 데이터 | 쓸 곳 |
|---|---|---|---|
| **단기예보(동네예보) 조회서비스** | 기상청 | 격자(nx,ny)별 날씨 | 지역별 현재/예보 날씨 |
| **관광코스별 관광지 상세 날씨 조회** | 기상청 | 관광지 좌표 기반 날씨 | "여행 갈 때 날씨" 표시 |
| **에어코리아 대기오염정보** | 한국환경공단 | 시도별 미세먼지/대기질 | 지역 대기질 뱃지 |
| **상가(상권)정보** | 소상공인시장진흥공단 | 전국 상가(음식점·카페 등) 위치/업종 | 맛집·카페 추천 대안 |
| **국가유산(문화재) 정보 오픈API** | 국가유산청(구 문화재청) | 문화재 목록·상세·이미지 | 지역 문화재/역사 명소 |
| **공연예술통합전산망(KOPIS) 오픈API** (`kopis.or.kr`) | (재)예술경영지원센터 | 공연·전시 목록/시설 | 지역 공연·전시 정보 |
| **국가대중교통정보(TAGO)** | 국토교통부/한국교통안전공단 | 버스·지하철·열차 정보 | 지역 이동/교통 |
| **철도 열차정보** | 한국철도공사(KORAIL) | 열차 시각·승차권 | 여행 이동 계획 |

### 참고 — 공공데이터는 아니지만 지도/이미지에 쓰면 좋은 것
- **카카오맵 / 네이버 지도 SDK·로컬 API**: 지도 렌더링, 장소 검색, 좌표 변환(무료 quota). *상용이지만 실무에서 가장 많이 씀.*
- **Coil / Glide**: 위 API의 이미지 URL 로딩용.

> ⚠️ 발급 팁: data.go.kr 서비스키는 **일반 인증키(Encoding/Decoding)** 두 종류가 오니, Retrofit `@Query`에 넣을 땐 보통 **Decoding 키**를 쓰고 인코딩 이슈에 주의. 승인까지 자동(즉시)~1일 소요.
